# Codex-Turnloom 2.1.1 产品与稳定性复审

最终产物：`../Codex-Turnloom-2.1.1-app.apk`，`com.codex.turnloom.app`，2.1.1 / versionCode 82。

SHA-256：`f020edd46893f1b712c3ef2baa586ce64c9d5c4b8c1e25082e493e1ac64f613e`。

当前交付仍是 React + Konsta UI + Vaul → Android Java WebView 容器，即 **App 化 DOM 容器（含 WebView）**。

## 复审结论

原有问题主要不是少几个视觉细节，而是“界面说可以，状态和生命周期却没有完整兑现”：首启失败后重试不发请求；前后台验证用了两套互不一致的计数器；缓存开关不控制缓存；更新状态依附设置页；助手回复被当成推理日志；静态测试能靠注释通过。此前的编译/方法存在检查不足以证明产品可用。

本轮从新用户流程和视觉触摸两个独立视角复核，主会话检查实际实现，随后仅修复确认问题。独立审查以旧 2.1.0 为基线；本报告中的最终设备结果来自新 2.1.1 实际安装包，不把旧报告当作新包通过。

## 已修复的设计与实现问题

| 问题 | 当前处理 | 验证 |
|---|---|---|
| 局域网 HTTP 只允许编译期几个示例 IP | Android 允许原生 HTTP；BridgeContract/NativeHttpPolicy 仍强制私网、显式 origin 配对、`/api/*` 和同源重定向。WebView 仍阻止远程页面/子资源 | 原生编译与 URL 单元测试；模拟器经真实原生 HTTP 连接 |
| 新配对失败后的“重试”不工作 | 根据当前表单、最近 QR 或已保存机器真正重试；401 展开表单并清除失效码 | 实机 401 → 输入新码 → 重试 → 工作台 |
| 冷启动/前后台验证可能永久被判过期 | 连接 transition 只由 sessionStore 管理，AppRoot 不再传独立的 React 生命周期序号 | 直接执行生产状态模块的重复重验证测试 |
| 切换不可用服务后没有恢复入口 | 连接错误页提供已发现的服务；可切回可用 Codex，无需再次扫码 | PI 503 → 恢复 Codex 实机流程 |
| 跨服务详情/筛选状态残留 | 激活不同 scope 时清掉旧详情、抽屉和筛选；旧请求结果不能再更新在线状态 | token、scope、迟到结果与导航测试 |
| “保留上次会话”开关无效 | 关闭后停止读写并删除本机该电脑的持久化会话缓存 | 存储行为测试 |
| 清缓存导致在线会话列表消失 | 清除磁盘缓存不清掉正在显示的真实列表 | 存储/内存状态断言 |
| 草稿返回后消失 | 草稿按机器、服务、threadId 分别保存；成功发送才清除，失败保留 | 重开详情及同 ID 服务隔离测试 |
| 消息详情永久加载、回复不更新 | 明确 loading/loaded/error；空消息显示空态，失败可重试；仅前台串行定时刷新 | 实机空消息结束加载；加载状态测试 |
| 普通助手回复被展示为“推理过程” | 仅 thinking/reasoning 类型进入推理区，不再把普通回复复制过去 | 源码与类型检查 |
| 更新状态随 Tab/权限页卸载丢失 | 应用级更新 store 持续订阅 native 回调；暂停、已校验、安装取消状态保留 | 暂停 → 首页 → 设置 → 继续下载实机验证 |
| 取消后旧下载与新下载可能重叠 | 独立运行标志，取消断开真实连接，旧线程结束后才允许新任务；续传文件绑定包 SHA | 实机取消与非零 Range 续传 |
| 进度把字节数当时间计算 | 用单调时钟节流进度回调 | 编译、源码核对、实际下载 |
| 安装交接被系统立刻取消结果 | 去掉 NEW_TASK，使用当前 Activity 返回栈；安装动作回到 UI 线程 | 系统 PackageInstallerActivity 确认页；取消返回保留 ready |
| Android 8/8.1 使用 API28 成员 | 版本号、签名查询增加 API 分支，旧版本回退 versionCode/signatures | 编译通过，API26/27 真机尚未验证 |
| 主按钮传 style 后丢失全宽/命中区 | ActionButton 从 rest 中单独取 style，合并后不再被属性展开覆盖 | 320px 下创建按钮 280×44px |

| 小字及状态对比度低 | 次要文字改#636366；保留装饰系统色，新增深蓝/绿/红用于实心动作与状态文字 | 共享组件与 token 更新；已同步主视觉合同 |
| 忘记电脑无确认、缓存后果不清 | 设置页增加确认抽屉，明确清除配对和该电脑会话缓存，不删除电脑会话 | 确认与取消保留连接实机流程 |
| 构建测试只匹配 cmd 字符串 | 删除注释绕过，真实启动成功/失败子进程，验证空格/引号参数、非零退出码和日志 | 新增启动器行为测试 |

## 仍需明确保留的边界

1. **真实镜头 QR 识别未完成**；权限、相机占用和取消不等于解码成功。
2. **实际点击系统“更新”后的覆盖安装未执行**。已验证安装确认页和取消恢复，保留正式82版及已有数据。
3. **生产桌面8787入口没有迁移**，公网、真实桌面二维码和生产升级链路未切换；临时fixture成功不代表生产入口已支持双服务。
4. **API26/27未实机验证**，只有兼容分支与编译证据；本轮设备为Android15。
5. `secureGet/Set` 仍使用应用私有 MODE_PRIVATE SharedPreferences，**未做应用层加密**；不能称为已实现加密凭据存储。
6. 已验证核心几何与触摸，不宣称全设备视觉/物理键盘/性能矩阵通过。独立视觉报告中的单帧空白仅作为动画现象，未证明永久缺陷，未扩展修复。
7. 当前签名为既有测试证书。未提交、推送、执行生产服务迁移或公网发布。
