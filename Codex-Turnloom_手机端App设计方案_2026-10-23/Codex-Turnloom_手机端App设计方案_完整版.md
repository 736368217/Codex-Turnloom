# Codex-Turnloom 手机端 App 设计方案 · 一页纸速览

- 版本：2026-10-23
- 用途：给设计 AI / 外部设计师的交接速览
- 完整规格：见同目录 `01`–`07` 号文档
- 视觉参考：见 `screens/`、`brand/`

## 1. 产品是什么

**Codex-Turnloom** 是一个私有、自托管的移动工作台，把正在电脑上运行的 **Codex Desktop** 延续到手机。

电脑仍然是数据和执行的源头；手机通过局域网或 HTTPS 连接电脑上的本机服务，查看对话、任务进度、工具记录和权限请求，并发送新消息、排队、插入或停止任务。

它不是远程桌面，不会把电脑画面传到手机，只呈现 Codex 工作流真正需要的内容。

## 2. 一句话价值

> 离开电脑时，仍然知道 Codex 在做什么，并且能接住它。

## 3. 目标用户

- 长时间使用 Codex Desktop 的开发者、产品经理、研究者、独立创作者
- 经常离开工位，但需要及时查看任务进度或处理审批的人
- 有多台电脑（办公室 / 家里 / 实验室）的人
- 对隐私敏感、希望数据留在自己电脑上的用户

## 4. 核心任务（按优先级）

1. 扫描二维码，把手机连接到正在运行 Codex 的电脑
2. 在对话列表中找到正在进行的任务
3. 阅读消息、思考状态、工具记录和权限请求
4. 在手机上处理审批，或发送新消息 / 排队 / 插入 / 停止任务
5. 在多台电脑之间切换，并保留每台电脑的连接状态

## 5. 设计关键词

安静、可信、轻量、效率、单手可用、信息密度可控、状态一眼可见、Android 原生外壳 + WebView 工作区。

## 8. 设计任务

请在**保留现有信息架构和功能范围**的前提下，为 Codex-Turnloom 的 Android 手机端做一套新的视觉与交互方案：

- 更清晰的信息层级：先看到任务状态，再看到消息内容
- 更安静的操作界面：只保留一个主操作蓝，减少彩色按钮竞争
- 更适合单手：发送、停止、审批、返回都在拇指可达区域
- 更可信：隐私、连接状态、发送结果必须明确可见
- 更一致：统一圆角、间距、图标、状态色和组件状态

**不要求**改变产品定位，**不要求**做远程桌面，**不要求**把手机端做成完整 IDE。

## 9. 交付边界

- 目标平台：Android 手机（390×844 基准，兼容 360–430dp 宽度）
- 语言：简体中文为主，保留英文版本扩展空间
- 主题：浅色为主；深色可作为可选扩展
- 形态：Android 原生外壳（电脑选择 / 扫码 / 顶栏）+ WebView 工作区
- 设计产物：关键页面高保真、组件库、设计令牌、交互说明、状态清单

# 01 产品与设计简报

## 1. 产品身份

- 产品名：**Codex-Turnloom**
- 中文定位：**把正在电脑上运行的 Codex，完整延续到你的手机里。**
- 产品类型：私有、自托管的移动控制台（mobile control desk）
- 平台形态：
  - Android App：原生外壳，负责电脑选择、扫码、设备存储、顶栏、通知、更新
  - 移动 Web 工作区：运行在 App 的 WebView 中，负责对话列表、消息流、输入区、审批、目标等
  - 本机服务：运行在电脑上，读取 Codex Desktop 数据并通过本机 IPC 转发操作
- 非官方项目：依赖 Codex Desktop 的本地数据与 IPC，Codex Desktop 更新后可能需要适配

## 2. 要解决的问题

Codex Desktop 是长时间运行的任务型产品。用户经常会：

- 离开工位去开会、吃饭、通勤，但想知道任务有没有完成
- 在手机上收到“需要审批”的提示，却必须回到电脑前才能点“允许”
- 突然想到一个补充要求，但不想重新打开电脑、找到对话、输入
- 在多台电脑之间切换，记不清哪台机器上跑着哪个任务
- 用远程桌面看手机屏幕，字太小、操作太重、流量也大

现有远程桌面方案的问题是：**把整个电脑搬到了手机上，而不是把 Codex 工作流搬到手机上。**

## 3. 解决方案

Codex-Turnloom 把 Codex 工作流拆成手机上真正需要的部分：

- **看**：对话列表、消息、思考状态、工具调用、目标、用量
- **批**：权限请求、等待确认的交互
- **说**：发送新消息、排队、插入、停止
- **切**：多台电脑的保存、状态检测与切换
- **提醒**：任务完成后发系统通知

电脑仍然是唯一的数据源和执行端。手机只是一个受访问码保护的、轻量的控制面。

## 4. 核心价值

1. **不断线**：离开电脑也能知道 Codex 在做什么
2. **接得住**：审批和补充指令不用回到电脑前
3. **看得懂**：只呈现工作流需要的信息，不复制桌面
4. **信得过**：数据留在自己电脑上，连接状态和发送结果明确可见
5. **切换快**：多台电脑、多个任务，一眼找到

## 5. 目标用户

### 主要用户

- **重度 Codex Desktop 用户**：每天有多个长任务在跑，需要随时查看进度
- **开发者 / 产品经理 / 研究者**：任务以对话和工具调用为主，需要读过程、做判断
- **多机用户**：办公室电脑、家里电脑、实验室机器同时使用
- **隐私敏感用户**：希望自托管，不接受把对话上传到第三方云

### 用户特征

- 熟悉 Codex 的基本概念（对话、任务、工具、审批、模型）
- 使用场景碎片化：会议间隙、通勤、睡前、离开工位
- 手机操作以单手为主，注意力时间短
- 对“任务是否还在跑”“有没有卡住”“审批有没有提交成功”非常敏感

## 6. 典型场景

### 场景 A：离开工位，查看长任务

用户在电脑上让 Codex 重构一个模块，预计 20 分钟。出门前用手机扫一下二维码，路上打开 App，看到任务仍在运行、当前在调用哪个工具、已经运行多久。

**设计重点**：任务状态、运行时长、最近一条消息、工具记录默认收起。

### 场景 B：会议中收到审批

Codex 需要写入一个目录，桌面端弹出审批。手机通知提醒，用户打开 App，在对话里看到红色交互卡片，点“是”或“一直是”。

**设计重点**：审批卡片必须在消息流中足够醒目；按钮要适合单手点；提交后要有明确的“已提交”反馈。

### 场景 C：补充一句要求

用户在排队等咖啡，突然想到一个边界条件。打开当前任务，输入一句话。因为任务还在运行，需要选择“排队”还是“插入”。

**设计重点**：运行中发送方式必须可见、可理解；队列中的消息要能编辑、取消、转为插入；发送失败要保留原文。

### 场景 D：多台电脑切换

用户在办公室和家里各有一台电脑。手机里保存了两台设备，打开 App 先看到电脑列表，显示在线 / 离线 / 正在检测，点进去继续对应电脑上的会话。

**设计重点**：设备身份、备注、地址、在线状态、连接反馈。

## 7. 设计原则

1. **电脑是源，手机是窗**：不制造“手机本地也有完整数据”的错觉
2. **一屏一任务**：对话工作台只围绕当前任务，不堆叠无关信息
3. **状态先于内容**：运行中 / 等待处理 / 已结束 / 离线，要先于正文被看到
4. **单一操作色**：蓝色只用于主操作、选中和链接；其他颜色只表达语义
5. **触控优先**：主要操作在拇指区，最小 44dp，避免小图标密集排列
6. **安静的界面**：中性表面、低对比边框、克制的阴影，不使用装饰性渐变
7. **可恢复**：发送失败、网络中断、审批失败都要有明确下一步
8. **隐私可见**：访问码、设备本地存储、连接范围用简短文案说明

## 8. 非目标

- 不是远程桌面，不传输完整电脑画面
- 不是完整的 IDE，不在手机上编辑代码
- 不是云端协作工具，不引入账号体系和多人共享
- 不是社交聊天产品，不强调表情、已读、在线状态等社交信号
- 不在本期做平板 / 折叠屏 / 桌面端专门布局（可作为后续扩展）

## 9. 设计约束

- Android 原生外壳与 WebView 工作区需要视觉连续，不能像两个产品
- WebView 内需要适配 360–430dp 宽度、刘海屏、手势导航、软键盘
- 中文文案为主，需考虑英文扩展后的长度变化
- 消息可能很长，包含 Markdown、代码块、表格、图片、文件
- 对话可能非常长，需要分页、缓存、滚动位置保持
- 网络可能不稳定，发送结果可能“不确定”，设计必须避免误导
- 触控目标不能小于 44dp；当前实现中部分 32–40dp 控件需要在 redesign 中修正

## 10. 设计成功指标（建议）

- 从打开 App 到进入目标对话的步骤数 ≤ 3
- 审批从看到到提交完成 ≤ 2 次点击
- 发送后 1 秒内能看到“发送中 / 已发送 / 失败”的明确状态
- 单手可触达发送、停止、审批、返回
- 小屏 360dp 下不出现横向滚动、文字截断导致的语义丢失
- 用户能准确说出“任务在运行 / 等待我处理 / 已结束”
- 视觉上只保留一个主操作蓝，其他颜色均有语义

## 3. 导航规则

1. **App 启动**：总是先进入电脑选择页；已保存电脑并行检测在线状态。
2. **进入电脑**：点击电脑行进入 WebView；顶栏显示电脑名和在线点。
3. **返回优先级**（Android 返回键 / 手势）：
   - 先关闭当前 Web 浮层（目标编辑、模型面板、插件/技能菜单、图片选择菜单、侧栏）
   - 再关闭对话列表抽屉
   - 最后返回电脑选择页
4. **对话列表**：选择对话后自动关闭抽屉（窄屏）；抽屉可通过遮罩、返回或左上按钮关闭。
5. **新对话**：在列表中插入“新对话”草稿项，右侧显示“输入消息开始新对话”。
6. **通知深链**：点击完成提醒通知，直接打开对应电脑和对话。
7. **外部链接**：消息中的网页链接交给系统浏览器打开，不覆盖当前 App 页面。
8. **文件下载**：调用 Android 系统下载；完成后可从系统通知打开。
9. **图片预览**：在 App 内全屏预览，支持双指缩放；返回关闭预览。
10. **多电脑**：每台电脑的访问码独立保存；切换电脑不丢失当前对话草稿。

## 4. 关键流程

### 4.1 首次连接

```text
启动 App
  → 电脑选择（空状态）
  → 阅读“扫描电脑上显示的设备码”
  → 扫描二维码 / 手动输入
  → 识别设备（名称、地址、访问码）
  → 保存到手机本地（Keystore 加密访问码）
  → 回到电脑列表，检测在线
  → 点击电脑
  → 原生顶栏 + 加载进度
  → 访问码通过（或已记住）
  → 对话列表 / 最近对话
  → 使用指引（首次）
```

### 4.2 继续一个正在运行的任务

```text
打开 App
  → 电脑列表（在线）
  → 进入工作区
  → 对话列表（按项目 / 按最近）
  → 选择“运行中”的对话
  → 打开最新 40 条消息
  → 查看状态：正在处理 · 运行时长
  → 工具记录默认收起
  → 输入补充内容
  → 选择“排队”或“插入”
  → 发送
  → 看到“已排队 / 已插入 / 发送失败”
```

### 4.3 处理权限审批

```text
消息流出现红色“交互”气泡
  → 标题“等待确认”
  → 阅读请求说明
  → 点击“是 / 否 / 一直是”
  → 按钮进入“正在提交审批…”
  → 成功：“审批已提交”
  → 失败：“审批提交失败：原因” + 保留重试
```

### 4.4 多电脑切换

```text
工作区顶栏返回
  → 电脑列表（当前电脑显示在线）
  → 选择另一台电脑
  → 检测在线 / 离线
  → 在线：进入工作区
  → 离线：显示地址与“离线”，可编辑 / 测试连接 / 删除
```

## 5. 信息层级

### 对话工作台（从上到下）

1. **任务身份**：标题、消息数、运行状态
2. **目标**：一行目标摘要 + 状态（可展开）
3. **消息流**：按时间顺序；用户消息右侧、Codex 左侧、工具/提示/交互有独立语义色
4. **当前状态**：思考中 / 正在处理 / 运行时长
5. **输入区**：文本 → 附件 → 模型/插件/技能 → 发送/停止 → 队列
6. **反馈**：发送状态、错误、重试

### 对话列表（从上到下）

1. **品牌与数量**
2. **搜索 + 新对话**
3. **排序方式**
4. **分组标题（可折叠）**
5. **对话项：标题 + 状态 + 提醒标记**
6. **使用指引 / 隐私说明**

## 6. 内容与命名约定

- 对话：`对话`；任务状态：`运行中 / 等待处理 / 已结束 / 状态未知`
- 发送方式：`排队`（当前任务完成后发送）/ `插入`（立即插入当前任务）
- 审批：`需要处理`、`等待确认`、`是`、`否`、`一直是`
- 连接：`在线`、`离线`、`正在检测`
- 提醒：`提醒已开`、`完成提醒`
- 目标：`目标`、`进行中`、`已暂停`、`已阻塞`、`用量受限`、`预算受限`、`已完成`
- 错误：使用“原因 + 下一步”，例如“发送失败：网络超时”“审批提交失败：请重试”

# 03 视觉设计系统

## 1. 设计方向

**Apple-inspired calm workspace**：中性白灰表面、单一操作蓝、清晰的字号层级、稳定的触控几何、克制的阴影和动效。

关键词：

- **安静**：界面不抢任务的注意力，内容优先
- **可信**：状态、连接、隐私和发送结果都清楚可见
- **轻**：大量留白，低对比边框，少量分隔线
- **快**：主要操作在拇指区，反馈及时
- **一致**：同一套圆角、间距、图标和颜色规则贯穿原生外壳与 WebView

不要做成：

- 远程桌面的缩小版
- 社交聊天 App（大表情、渐变、气泡尾巴、花哨头像）
- 开发者 IDE（深色代码编辑器风格、密集工具栏）
- iOS 专属风格（`UIBlurEffect`、SF Symbols 专用形态）

## 2. 品牌

### 2.1 Logo

- 蓝底圆角方形（`#2563EB`）
- 两段白色开口环，形成“延续 / 循环”的意象
- 右上薄荷绿节点（`#56D9B5`）
- 左下珊瑚红节点（`#FF6B4A`）
- 圆角比例约为边长的 25%
- 最小使用尺寸：24×24px；App 图标 48×48px
- 安全边距：不小于 Logo 边长的 1/4
- 不在 Logo 上叠加文字、描边或阴影

### 2.2 品牌语气

- 简洁、直接、技术可信
- 中文用短句，不用感叹号
- 避免营销化措辞
- 示例：
  - “把电脑上的 Codex，延续到手机”
  - “电脑仍是数据源，手机负责查看和处理”
  - “所有内容仍保存在你的电脑上”

- 常用图标：返回、刷新、搜索、加号、发送、停止、工具、更多、关闭、眼睛、文件、图片、箭头

## 10. 动效

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 抽屉滑入 / 滑出 | 240ms | `cubic-bezier(0.22, 1, 0.36, 1)` |

| 分组折叠箭头 | 140ms | `ease` |
| 滚动到底按钮 | 160ms | `ease` |
| 思考中省略号 | 1.1s | `steps(4, end)` 循环 |
| 页面切换 | 180–240ms | `ease-out` |

规则：

- 不使用弹跳、旋转、缩放超过 1.03 的动效
- 尊重 `prefers-reduced-motion`，关闭非必要动画
- 加载状态用骨架或轻量 spinner，不使用全屏遮罩
- 发送按钮状态变化要即时，不依赖动画完成

## 11. 安全区与响应式

- 顶部：`env(safe-area-inset-top)`
- 底部：`env(safe-area-inset-bottom)`
- 左右：`env(safe-area-inset-left/right)`
- 断点：
  - `max-width: 760px` 且竖屏：手机布局（抽屉覆盖、消息单列）
  - `max-width: 520px`：队列项纵向排列
  - `max-width: 360px`：隐藏插件按钮，模型名进一步缩短
- 手机基准：390×844；兼容 360×800、412×915、430×932
- 横屏：不作为主要设计目标；需保证不崩溃、不横向滚动

- 工具气泡 `#2C2C2E`
- 不使用纯黑 + 纯白高对比大面积
- 保持语义色一致，但提高亮度

## 13. 无障碍

- 所有可点击元素有可见焦点态（2–3px 外发光）
- 图标按钮提供可读标签
- 状态文字与颜色同时存在
- 支持系统字体放大到 1.2× 不破坏布局
- 输入框有 placeholder 和 label
- 对话框焦点锁定，Esc / 返回可关闭
- 动效可关闭
- 触控目标 ≥ 44dp

## 14. 当前实现的观察与待优化点

> 这一节是给 redesign 的输入，不是要求照搬。

1. **两套强调色并存**：主界面已使用操作蓝 `#0066CC`，但目标条、队列、审批等旧组件仍有绿色 / 暖黄残留（如 `#1F6F62`、`#77A99D`、`#EAF4EF`），需要统一。
2. **工具开关视觉权重过高**：选中态是整块蓝色圆形 + emoji，容易与发送按钮竞争；建议改为中性图标按钮 + 明确开关状态。
3. **触控尺寸偏小**：部分图标按钮 32–40dp，低于 44dp 建议；重设计时统一热区。
4. **圆角不统一**：6/7/8/12/14/18 混用；建议收敛为 8/12/16/999。
5. **状态色接近**：运行橙 `#B86B18` 与等待红 `#B24C42` 在小字号下不易区分；建议配图标或更明确的文字。
6. **小屏输入区拥挤**：模型名、插件、技能、排队/插入、附件、发送/停止同时出现；360dp 下需要优先级与折叠策略。
7. **品牌名在访问码卡片换行**：`Codex-Turnloom` 在 390dp、28px 字号下会断成两行；可缩短字号或调整字距。
8. **旧版用量卡片与当前视觉不一致**：如果保留，需要重新纳入设计系统。

## 7. 反馈组件

### 7.2 加载

- 短反馈：底部 Toast 2s
- 可恢复错误：Snackbar + 操作按钮（重试 / 撤销）
- 不使用模态对话框展示普通成功提示

## 6.1 角色

你是一位资深移动端产品设计师，擅长 Android 工具类产品、信息密度控制、长会话阅读体验和设计系统建设。请为 **Codex-Turnloom** 设计一套新的手机端界面。

## 6.2 产品背景

Codex-Turnloom 是一个私有、自托管的移动工作台，把正在电脑上运行的 Codex Desktop 延续到手机。

- 电脑仍然是数据和执行的源头
- 手机通过局域网或 HTTPS 连接电脑上的本机服务
- 手机端负责：查看对话、任务状态、工具记录、权限请求；发送新消息、排队、插入、停止
- 不是远程桌面，不是完整 IDE，不是社交聊天 App

目标用户是长时间使用 Codex Desktop 的开发者、产品经理、研究者和多机用户。他们经常离开工位，需要快速确认任务状态、处理审批、补充一句要求。

## 6.3 设计目标

请在不改变信息架构和功能范围的前提下，达成以下目标：

1. **状态一眼可见**：运行中 / 等待处理 / 已结束 / 离线，必须先于正文被看到
2. **单一操作色**：只保留一个主操作蓝，减少彩色按钮竞争
3. **单手可用**：发送、停止、审批、返回都在拇指可达区域，触控目标 ≥44dp
4. **长会话可读**：消息层级清楚，工具记录可收起，代码块和图片不破坏阅读节奏
5. **反馈明确**：发送中 / 已发送 / 失败 / 排队 / 插入 / 审批已提交，不能让用户猜
6. **视觉统一**：原生 Android 外壳与 WebView 工作区看起来像同一个产品
7. **可信与安静**：中性表面、低对比边框、克制的阴影，不做装饰性渐变

## 6.4 目标平台与画布

- 平台：Android 手机
- 基准画布：**390×844dp**
- 需要检查：360×800、412×915、430×932
- 竖屏为主；横屏不崩溃即可
- 浅色主题为主；深色可选
- 中文 UI；英文扩展时不能溢出

2. **电脑选择（列表）**

3. **对话列表抽屉**

   - 底部的使用指引与隐私说明

4. **对话工作台**

   - 消息流：用户、Codex、工具、提示

## 9. 评审时必须追问的问题

1. 用户在 360dp 小屏上，第一眼能看到“运行中”还是只看到消息正文？
2. 审批失败后，用户是否知道下一步做什么？
3. 发送失败后，原文和图片是否还在？
4. 运行中，用户是否清楚“排队”和“插入”的区别？
5. 工具开关是否和发送按钮争夺注意力？
6. 多电脑场景下，用户是否能在 3 步内切换？
7. 键盘弹出时，发送按钮是否仍可见？
8. 断网时，页面是显示旧内容还是清空？
9. 颜色之外，状态是否还有文字/图标兜底？
10. 设计是否仍然像“Codex 工作台”，而不是一个通用聊天 App？

## 10. 常见扣分项

- 把“运行中”做成一个很小的灰点
- 用绿色表示所有“成功”和“在线”，用红色表示所有“错误”和“等待”，导致语义混淆
- 发送按钮、停止按钮、附件按钮大小相同且颜色都很重
- 审批按钮只有颜色，没有文字说明
- 队列条把输入区挤到屏幕外
- 工具记录默认展开，消息流被工具日志淹没
- 模型名、插件、技能在 360dp 下全部挤在一行
- 使用渐变、玻璃拟态、彩色气泡尾巴
- 把电脑选择页做成启动广告页
- 把“新建对话”做成巨大的悬浮按钮，遮挡内容
