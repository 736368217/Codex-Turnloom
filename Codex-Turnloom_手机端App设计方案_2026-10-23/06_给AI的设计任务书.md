# 06 给 AI 的设计任务书

> 这份文档可以直接复制给另一个设计 AI（Figma AI、v0、Claude、ChatGPT、Lovable、Galileo 等）。
> 如果对方支持上传文件，请同时上传本压缩包中的 `00`–`05`、`design-tokens.json` 和 `screens/`。

## 6.1 角色

你是一位资深移动端产品设计师，擅长 Android 工具类产品、信息密度控制、长会话阅读体验和设计系统建设。请为 **Codex-Turnloom** 设计一套新的手机端界面。

## 6.2 产品背景

Codex-Turnloom 是一个私有、自托管的移动工作台，把正在电脑上运行的 Codex Desktop 延续到手机。

- 电脑仍然是数据和执行的源头
- 手机通过局域网或 HTTPS 连接电脑上的本机服务
- 手机端负责：查看对话、任务状态、工具记录、权限请求；发送新消息、排队、插入、停止
- 不是远程桌面，不是完整 IDE，不是社交聊天 App

目标用户是长时间使用 Codex Desktop 的开发者、产品经理、研究者和多机用户。他们经常离开工位，需要快速确认任务状态、处理审批、补充一句要求。

## 6.3 设计目标

请在不改变信息架构和功能范围的前提下，达成以下目标：

1. **状态一眼可见**：运行中 / 等待处理 / 已结束 / 离线，必须先于正文被看到
2. **单一操作色**：只保留一个主操作蓝，减少彩色按钮竞争
3. **单手可用**：发送、停止、审批、返回都在拇指可达区域，触控目标 ≥44dp
4. **长会话可读**：消息层级清楚，工具记录可收起，代码块和图片不破坏阅读节奏
5. **反馈明确**：发送中 / 已发送 / 失败 / 排队 / 插入 / 审批已提交，不能让用户猜
6. **视觉统一**：原生 Android 外壳与 WebView 工作区看起来像同一个产品
7. **可信与安静**：中性表面、低对比边框、克制的阴影，不做装饰性渐变

## 6.4 目标平台与画布

- 平台：Android 手机
- 基准画布：**390×844dp**
- 需要检查：360×800、412×915、430×932
- 竖屏为主；横屏不崩溃即可
- 浅色主题为主；深色可选
- 中文 UI；英文扩展时不能溢出

## 6.5 必须覆盖的页面（P0）

请输出以下 7 个核心页面的高保真设计：

1. **电脑选择（空状态）**
   - 首次使用，解释“手机连接电脑”的模型
   - 扫码按钮、手动输入、隐私说明

2. **电脑选择（列表）**
   - 2–3 台电脑，展示在线 / 离线 / 正在检测
   - 名称、备注、地址、行菜单、添加另一台

3. **对话列表抽屉**
   - 品牌、对话数、搜索、新对话、排序
   - 置顶 / 项目 / 其他对话分组
   - 对话项：标题 + 状态 + 提醒标记
   - 底部的使用指引与隐私说明

4. **对话工作台**
   - 顶栏：标题、消息数、运行状态、目标、工具开关、刷新
   - 消息流：用户、Codex、工具、提示
   - 输入区：文本、模型、插件、技能、附件、发送/停止
   - 思考中状态与运行时长

5. **权限审批**
   - 红色交互气泡，说明请求内容
   - “是 / 否 / 一直是”
   - 提交中、已提交、失败三种反馈

6. **运行中排队 / 插入**
   - 队列条、队列项、编辑/取消/转为插入
   - “排队 / 插入”分段控件
   - 停止按钮
   - 队列为空与任务刚好完成的边界状态

7. **使用指引**
   - 首次进入的三步说明
   - 隐私说明与“开始使用”

## 6.6 建议补充的页面（P1）

- 访问码门
- 添加电脑（扫码 / 手动）
- 目标详情 / 编辑
- 模型与思考强度
- 插件 / 技能选择
- 完成提醒
- 用量信息（可选）

## 6.7 视觉方向

**关键词**：安静、可信、轻、效率、单手、清晰、克制。

建议：

- 页面背景：`#F5F5F7`
- 卡片 / 气泡：`#FFFFFF`
- 主文字：`#1D1D1F`
- 次文字：`#6E6E73`
- 边框：`#E0E0E5`
- 唯一主操作蓝：`#0066CC`
- 浅蓝选中 / 用户气泡：`#E8F2FF`
- 工具气泡：`#ECECF0`
- 提示：`#FFF4D8`
- 交互 / 审批：`#FFF0F0`

字体：

- 系统无衬线：`system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`
- 正文 15–16px / 1.45–1.55
- 标题 17–20px / 600
- 大标题 27–28px / 600–700
- 元信息 11–12px

形状：

- 圆角建议收敛为 8 / 12 / 16 / 999
- 触控目标 ≥ 44×44dp
- 主要按钮高 46–48dp
- 卡片内边距 12–16dp
- 页面左右边距 14–18dp

材质：

- 顶栏和输入区可用轻微半透明 + 模糊
- 不做大面积玻璃拟态
- 不使用装饰渐变
- 阴影只用于浮层和抽屉，不用于普通卡片

图标：

- 线性图标，1.8px 描边，圆角端点
- 尺寸 16 / 20 / 22 / 24px
- 不用 emoji 作为功能图标

## 6.8 关键交互要求

- 对话列表：选择对话后自动关闭抽屉；长按 520ms 打开上下文菜单
- 对话工作台：滚动到顶部加载更早消息，保持当前阅读位置
- 工具记录：默认收起；点击工具开关后显示
- 运行中：必须能选择“排队”或“插入”；显示停止按钮
- 发送：立即出现乐观气泡；显示发送中 / 失败 / 重试；失败保留原文和图片
- 审批：点击后立即禁用全部按钮；显示提交中 / 已提交 / 失败
- 返回：先关闭浮层，再关闭抽屉，最后返回电脑列表
- 键盘：输入区随键盘上移，不遮挡发送按钮
- 触控：所有主要操作在拇指可达区域；最小 44dp

## 6.9 需要避免

- 不要做远程桌面的缩小版
- 不要做社交聊天 App（气泡尾巴、渐变、表情、花哨头像）
- 不要做深色 IDE 风格
- 不要给每个功能分配独立颜色
- 不要让工具开关、刷新、附件等次要操作和发送按钮同等视觉权重
- 不要使用小于 12px 的关键状态文字
- 不要让状态只靠颜色表达
- 不要在 360dp 宽度下出现横向滚动
- 不要改变产品定位和信息架构

请输出：

2. **组件库**：按钮、输入框、对话项、气泡、审批、队列、模型/插件选择、对话框
3. **设计令牌**：颜色、字号、间距、圆角、阴影、动效
4. **交互说明**：每个页面的关键操作、状态切换、边界情况
5. **设计说明**：为什么这样设计，如何满足 6.3 的目标
6. **可选的深色模式**

如果输出格式支持：

- Figma frames 或可编辑的图层
- 页面命名：`S01_电脑选择_空`、`S02_电脑选择_列表`、`S03_对话列表`、`S04_对话工作台`、`S05_权限审批`、`S06_运行中排队`、`S07_使用指引`
