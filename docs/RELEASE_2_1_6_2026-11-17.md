## 1. 打开会话跳到最上方

`ChatDetailScreen` 原来没有任何「贴底」逻辑，`<main class="tl-detail-body">` 从 0 开始渲染，
于是 82 条消息的会话一打开就停在最早一条。现在：

- 首次拿到消息后 `scrollTop = scrollHeight`（下一帧再设一次，避免图片/markdown 撑高后偏）；
- 监听滚动，距底部 < 120px 视为「用户在跟最新」；新消息到达时若仍在跟，就继续贴底；
- 「加载更早消息」仍沿用原来的位置补偿（不会把视图甩到底部）；
- 切换会话时重置贴底状态。

## 2. 思考 / 工具输出没有和正文区分

旧实现有两个问题：thinking/tool 行被当成普通 `assistant` 消息塞进同一个气泡；同时页面底部
还有两个折叠块（推理过程 / 命令记录）把同样的内容再列一遍。现在改成三种独立区块：

| 类型 | 判定 | 渲染 |
|---|---|---|
| 思考 | `kind ∈ {thinking, reasoning, analysis}` | `.tl-thought`：浅灰底 + 左侧 3px 色条 + 「思考过程」标签，超过 180 字折成 4 行可展开 |
| 工具 | `role === 'tool'` 或 `kind ∈ {tool_call, tool_output, command, terminal}` | `.tl-tool`：工具名标题条 + 等宽 12px 正文，最高 220px 可滚动，失败态红色标题 |
| 提示 | `kind === 'error'` 或 `role ∈ {notice, system}` | `.tl-chat-notice`：暖黄底提示条 |

底部那两个重复的折叠块已删除（只保留「文件变更」）。

## 实测（真浏览器 + 真实 8799 数据）

做法：把 `vite build` 产物用本地静态服务器托管，同源代理 `/api` 到 8799，注入只做 HTTP 转发的
`TurnloomNative` 桩并种一份配对状态，然后用 ego 的 Chromium 打开会话 `fclash`（82 条消息、含真实
工具输出与失败提示），量 DOM：

```
scrollTop 5893 / scrollHeight 6275 / clientHeight 382  → distanceFromBottom = 0
rows 82 · bubbles 78 · tools 2 · notices 2 · 老折叠块 0
toolBody.fontFamily = ui-monospace, SFMono-Regular, Menlo, Consolas, monospace
firstRow = "本轮执行失败（PROVIDER_ERROR）…"   lastRow = "界面重做完成并已发布：2.11.59…"
```

即：打开就停在最新一条；工具输出与失败提示各自独立成块，等宽字体与正文可区分；旧的重复折叠块已消失。

## 限制（如实说明）

- 该会话的 82 条消息里没有 `thinking` 行——PI 后端不把模型的思考内容写进消息表，
  所以「思考过程」块只在后端真的下发 `kind=thinking/reasoning` 时出现（Codex 后端会）。
  这不是样式没做，是这条数据里没有思考内容。
- ego 的整页截图通道本次超时（已知的宿主截图卡死现象），本轮证据是 DOM 度量而非像素图。
