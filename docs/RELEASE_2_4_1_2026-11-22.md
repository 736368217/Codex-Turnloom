# 2.4.1 — 日志只留自动上传，收掉 2.4.0 的尾巴（2026-11-22）

App `2.4.1`（versionCode `100`）· 电脑端服务同步升级（日志保留策略）

这一版只收两件 Human 点名过的事与 2.4.0 明确推迟的尾巴，没有新功能。

## 日志：自动上传覆盖所有真实发送路径

- 诊断 sheet 里的「上传日志」按钮**已删**，改成两行真实状态：「日志上传：自动 · 每次发送成功后」与「最近上传：<时间> · 已上传 N 条 / 失败（原因）/ 尚未上传」。口径要说准：**每次成功发送之后都会尝试把「待上传的记录」送出去（最近 200 条）；没有待传记录时不发请求**——不是「每次发送都会上传」。此前自动上传只覆盖「已有会话、空闲首发」一条路径，2.4.1 把**排队发送**与**新会话首发**也补上了，所以删掉手动入口后，「自动上传」对三条真实发送路径都成立。
- 服务端 `logs/phone/` 加了**目录级预算**：总字节 16 MiB、日文件 50 个（每份日文件仍裁到 1,000 行，所以 50 个文件即 5 万行上限）。超预算按文件名里的日期**从最旧整份删**；永不删最新一份，删失败就停手。清理报告写在服务端日志里，不进 HTTP 契约。

## 对话与设置

- **等待审批时的输入区提示**：「先处理审批，或排队下一条」。只在你已经开始输入时出现——审批卡本身就在消息流里，空输入时再挂一句就是噪音。优先级：notice（队列暂停等）> waiting > running。
- 危险区「忘记这台电脑」的图标从 `Trash2` 换成 `LogOut`：它只解除配对，不删电脑上的任何数据。`Trash2` 的语义（删数据）与实际行为不符。

## 工程：让「字段名写错」在编译期就红

- `ThreadMessage` 的字段从「一个 index signature 兜住一切」改为**显式声明 24 个真实读点**；`[key: string]: unknown` 已删除。
- `/api/threads/:id/messages` 的返回在边界跑一次 `normalizeThreadMessages()`：`items|messages` 统一、`timestamp` 从 `createdAt/updatedAt` 回填。2.4.0 的日期分隔 bug（服务端只给 `timestamp`、屏幕读 `createdAt`）属于这一类。
- 反向夹具 `test/fixtures/message-typo.ts` 故意写错字段名，测试断言它**编不过**；哪天有人把 index signature 加回来，这条会先红。
- 发布漂移哨兵搬进 GitHub Actions：每 6 小时 + `release: published` 各跑一次，不再依赖某台机器上的 Host 执行器。

## 明确不做

- **诊断行文案更精确化（2.4.2）**：sheet 第一行现在写「自动 · 每次发送成功后」（触发时机），2.4.2 改成「自动 · 失败记录随发送送出」，同步 `app-ia.test.cjs` 的字符串断言。这不影响本版对外口径——本说明用的是精确说法。
- **当前电脑卡不挂平台标记**：状态行回答「这台电脑现在通不通」，平台卡在下一层且默认展开；非当前电脑才用 `CX / PI`。Human 看过 2.4.0 实物仍要当前卡也挂，再改。
- **`ThreadSummary` 的 index signature 不动**：这版只收 `ThreadMessage`；摘要行的收窄需要连带改列表与搜索的读点，留到 2.5.0。
- 日志清理不上云、不引入新存储后端。
