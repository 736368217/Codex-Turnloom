## 缺陷与根因

### 1. 「手机上选了 DS，电脑端跑的是别的模型」

三层原因，缺一不可：

1. **桥根本没下发模型**：`third-party/turnloom-pidesktop/plugin/main.js` 的 `thread-follower-start-turn`
   分支只读 `input`，完全忽略 `turnStart.request.model`（2026-11-06 为了不再每轮弹宿主的危险确认框
   而写了 `// Intentionally no ensureSendableModel()`）。于是**任何**手机端模型选择都不生效。
2. **服务端静默替换**：`server.js normalizeTurnSettings` 是 `models.find(id) || 默认模型`，
   手机端 id 与目录差一个字符（供应商改名/模型下架/大小写）就被换成默认模型，且不报错。
3. **客户端静默回退**：`app/src/lib/chatContract.ts resolveTurnPreference` 在「已选模型不在
   当前目录」时退回目录里的第一个模型，选择器显示的也变成别的模型。

修复：

- 桥：`thread-follower-start-turn` 在**请求里显式带模型**时才解析并 `ensureSendableModel`
  （`session/configure` + `confirm:true`，宿主照常弹确认框）。同模型同强度仍然跳过，
  普通发送（不选模型）绝不弹框。`applyModelIfChanged` 现在也比较思考强度，
  只改强度也会真的下发一次。`sessionModelPair` 增加 `thinking_level`，并用
  `PRAGMA table_info` 探测该列，老库/测试库缺列时退回两列查询。
- 服务端：新增 `resolveTurnSettings` / `catalogModelMatch`。精确匹配 → 忽略大小写 →
  「/」后模型名唯一命中时兜底（并记录 remap）；**都不中直接 409 `MODEL_NOT_IN_CATALOG`**，
  绝不用别的模型代替发送。`/api/send` 响应回传 `model` / `effort` / `requestedModel`。
- 客户端：`saved.model` 即使不在目录里也原样保留为选择（synthetic entry），不再静默换成第一个模型。

真机口径：`node test/turn-settings-resolution.test.js` 5 项钉住「不替换 / 可 remap / 默认档」；
实机 `POST /api/send {model:"ghost/not-real"}` 返回
`409 {"error":"所选模型「ghost/not-real」不在电脑端模型目录里…本轮不会用其它模型代替发送。"}`。

### 2. 会话列表能看见已归档会话

- Codex 侧有 `threads.archived` 与 `archived_sessions` 目录，客户端 `isArchivedThread` 已能识别。
- PI 侧 `sessions` 表**没有 archived 列**（只有 `deleted_at`），服务端拿不到归档标记，
  因此新增本机归档表 `app/src/lib/threadArchive.ts`（localStorage，按 thread id，上限 2000）。
- 会话页默认隐藏归档会话，标题下方显示「显示归档会话（N）」切换；每行尾部有归档/取消归档按钮
  （`TaskStream` 新增可选 `onArchive` / `isArchived`，首页不传则不渲染该按钮）。

### 3. 每次打开都要重新连接、断连就不可用

- `AppRoot`: `session.harnesses.length > 0` 即渲染工作台，后台 `revalidatePersisted()`。
- `AppShell`: 非 `ready` 状态显示 `.tl-conn-banner`（正在重连…（先显示上次缓存）/ 离线：显示上次缓存的内容 + 重试）。
- `sessionStore`: 新增 `retryPersistedSession()`。

### 4. 图片占位、相册、更新面板

- 输入框附件托盘改单行横向滚动（`flex-wrap:nowrap; overflow-x:auto`），缩略图 `max-width:168px`。
- `AttachmentPicker`：`kind=image` 时 Android 13+ 走 `MediaStore.ACTION_PICK_IMAGES`（系统照片选择器），
  旧版本走 `ACTION_GET_CONTENT` + `image/*`；`kind=file` 仍是 `ACTION_OPEN_DOCUMENT`。
  启动失败回退一次 `GET_CONTENT`，不新增任何权限。
- 设置页更新卡片：内边距 `12/16/8`→`10/16/6`，说明文字 12/18 → 13/19，进度条 10 → 8。
- 模型面板：`efforts.length<=1` 时不再渲染「点不动」的分段按钮，改文案说明
  （`.tl-mp-effort-note`，本轮补上样式）。

## 服务端补强（同版本，2.1.5 客户端无需重装）

2.1.5 发布后补的两处修正都在 `server.js`，重启 8799 即时生效。

### 1. 换模型不再需要有人坐在电脑前

实测结论：`session/configure` 在宿主里属于 dangerous，插件调用会挂起等桌面确认
（25 秒超时，`plugin.log` 里连 `desktop.invoke` 都没出现）。因此改为**直接写会话行**：
`UPDATE sessions SET provider_id=?, model_id=?, thinking_level=? WHERE id=?`。
写前确认会话空闲（运行中返回 409 `MODEL_SWITCH_BUSY`），写后回读校验，不一致就 409。
排队发送（`mode=queue`）不在入队时切，改由 drain 在空闲时切。

证据（双向切换，全程只调 HTTP）：`d6a4cc18` 从 `77625 free/deepseek-flash`
→ `wb反代/deepseek-v4.1-flash`，新一轮 `turns.provider_id/model_id` 与写入值一致；
反向切换同样成立。响应体回传 `model/effort/requestedModel`，手机端显示实际生效值。

### 2. 归档状态直接跟 PI-Desktop 一致

PI-Desktop 的归档是渲染层状态，存在 `D:\pi-data\data\sidebar-preferences.json` 的
`sessionMeta[id].archived`（数据库里没有这一列）。服务端现在：

- `GET /api/threads` 合并该文件的归档标记（实测 257 条会话里 180 条已归档）；
- `POST /api/threads/:id/archive {archived}` 写回同一文件（原子替换，只改该 id 的
  `archived`，其余逐字保留），实测开关往返成功。

手机端 2.1.5 已隐藏 `archived:true` 并带「显示归档会话」开关，不需要重装。

## 遗留

- 手机端「归档」按钮目前只写本机（localStorage）；写回 PI-Desktop 需要下一次 App 发布
  接上 `/api/threads/:id/archive`。桌面侧归档已经能正确同步到手机。
- 直接写 `sessions` 行依赖「宿主按数据库选模型」（已实测）。若 PI 改为内存缓存会话模型，
  这条路径要重新验证。
