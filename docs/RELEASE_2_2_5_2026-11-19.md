## 这一版改了什么（一句话版）

- **头部**：标题下面显示会话所属项目（没有项目就不占位）；当前模型移到右上角，点开同一张面板；`@` 从输入舱顶行移到工具行，与拍照/图片/附件平级。
- **模型面板**：只列「电脑端已加入且启用」的模型，顺序照桌面软件；默认模型按「这个会话上次用的 → 这台机器最近用过的（且仍在集合内）→ 桌面默认」回退；当前会话的模型被从电脑端移除时，面板顶部只多一条**不可选**的「电脑端未加入」状态行，头部 chip 同步显示「已移除」——不静默换模型。
- **会话列表**：置顶会话在两个视图（按时间/按项目）最上方各出现一次、不重复，0 条时整组不渲染；视图切换是可横滑的胶囊条。
- **Windows 端**：新增日志打包与上传（`/api/admin/logs`、`/api/admin/logs/upload`），包内只保留白名单字段、截断与遗漏都写成显式事实；控制台接入「上传日志」「检查更新」；打包脚本在出包前硬校验 APK 签名证书。

## 已知限制

1. **`android:debuggable="true"`**：本版沿用了 `buildType=debug` 的出包路径（2.2.3/2.2.4 也是）。装在有 USB 调试的设备上，`adb shell run-as com.codex.turnloom.app` 可以读到应用私有数据（含本机保存的访问码）。改成 `buildType=release`（`debuggable=false`）排进 2.2.6，不在发布夜改构建路径。
2. **手机连的那台 de 走 Codex Desktop 路径**：面板会显示 Codex Desktop 的**完整目录**——这台机器升到 2.2.5 后实测 **16 个**（`gpt-6.1-sol`、`gpt-6-astra`、`gpt-5.x` 系列、`gpt-image-2`/`gpt-image-2.5`）。**这是正确行为，不是本版没生效**：2.2.2 及更早的服务端给的是内置兜底目录（4 条），2.2.5 读的是桌面真实目录。Codex 没有「已加入模型」这个概念，所以「只列已加入的几个」只在后端是 PI 时成立——PI 才有 `providers.config_json.models`。要切到 PI：`CODEX_LAN_PI_NATIVE_QUEUE=1`，或控制台设置页「IPC 管道」填 `\\.\pipe\pidesktop-codex-ipc`；**切换前必须先确认 PI 桥在**，否则发送会直接报错。本版不带这个开关（排 2.2.6，同时加 `modelsSource` 让手机端能认出后端）。
   - 新会话的模型取值顺序是 `已保存选择 → 本会话的 model → 这台机器上次用过的模型（仍在集合内才用）→ 目录默认`。de 上升级后实测该值是 `gpt-6-astra`，即「沿用这台机器上次用过的那一个」，不是「目录默认 `gpt-6.1-sol`」。
3. **更新入口的真机点击未验，而且 2.2.4 用户不能靠它升级上来**：`查看并安装` 只在「清单版本 > 已装版本」时出现。2.2.5 上线后，装了 94 的设备看到「已是最新」，按钮不出现；装 93 的设备（2.2.4）能看到按钮，但那份包里的代码是修复前的——Rhea 20:24 在模拟器上实测：2.2.4 未配对时「检查应用更新」能正常报「发现新版本 2.2.5」，**点「查看并安装」界面没有任何反应**（`25fe231` 的 sheet host 只存在于 2.2.5）。所以**首跳只有两条：已配对的走设置页升级；未配对的必须手装一次 2.2.5**。本版只能给「真 bundle（与 APK 同字节）走通全流程」这一级证据，**真机首次点击留到 2.2.6 发布时补**（届时 2.2.5 会看到 2.2.6 的入口）。
4. **控制台窗口内真人点击未验**：「上传日志」「检查更新」两张卡片只验了代码路径与端点（含缺令牌、R2 拒收两条失败分支）。在 Electron 窗口里点一次待补。
5. **公网入口当日不可达**：`https://121.40.69.97:18789` 连不上，原因是 VPS 主机密钥与 `~/.ssh/known_hosts` 第 9 行不一致，隧道被 `StrictHostKeyChecking=yes` 拒绝（已持续数小时）。与本版构建/分发无关；确认主机密钥变更来源后再改信任设置。在此期间手机走局域网。
6. `supervisor.log` 4.8 MB 的根因是上面那条隧道崩溃循环，而写这个文件的是**旧版计划任务**（不是新控制台）。不要先删计划任务——它现在是 8787 与隧道的托管体。处理顺序写在 `docs/LOGS.zh-CN.md` §4.1。

## 安装

**手机**

1. 装 `Codex-Turnloom-2.2.5-app-debug.apk`（覆盖安装，签名一致，不用卸载）。
   - **从 2.2.4 上来的必须手装这一次**：2.2.4 的未配对「查看并安装」是死的（见已知限制 3），已配对的可以走设置页「检查更新」，未配对的没有别的入口。
2. 已配对的机器保持原地址；未配对时填 `http://<电脑局域网 IP>:8787`（本机 de）并输入访问码。

**电脑（把 de 升到 2.2.5）**

用升级脚本，不要手工解压——脚本会校验清单摘要、备份当前安装、覆盖、跑 `npm ci --omit=dev`、写入新清单，失败自动回滚。

**由旧计划任务托管的机器（本机 de 就是）要加 `-SkipRestart`**：脚本的 `Stop-Supervisor` 只结束命令行里带目标根的 `windows-supervisor.ps1`，**不碰计划任务**；而旧任务每 ~59 秒触发一次，脚本的 `Wait-Health` 只等 45 秒——不加这个参数，能否通过取决于计划任务下一次触发是否落进窗口，没落进去就会回滚。

```powershell
cd C:\Users\Administrator\Documents\Codex\codex-turnloom
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\update-turnloom.ps1 `
  -PackageZip public\downloads\turnloom-2.2.5-server.zip `
  -DesktopRelease public\downloads\desktop-release.json -SkipRestart

# 文件与清单已替换（exit 0，不重启不校验）。结束旧进程，让计划任务在 5 秒内用新代码拉起：
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -like '*Documents\Codex\codex-turnloom\server.js*' } |
  ForEach-Object { taskkill /PID $_.ProcessId /T /F }
```

若这台机器是由控制台托管的（没有那张计划任务），去掉 `-SkipRestart`：脚本会自己重启并回读校验。

`-DesktopRelease` 不能省：包内自带的 `desktop-release.json` 永远是上一版（清单要描述 zip 自身的 sha256，不可能自指），不传这个参数，装完控制台「检查更新」会继续显示「最新 2.2.4」。

核对：

```powershell
Invoke-RestMethod http://127.0.0.1:8787/api/health -Headers @{ 'x-access-token' = '<访问码>' } | Select-Object version
Invoke-RestMethod http://127.0.0.1:8787/api/desktop/update -Headers @{ 'x-access-token' = '<访问码>' } | Select-Object updateAvailable,upToDate
```

第一条应为 `2.2.5`；第二条应为 `updateAvailable: false, upToDate: true`（清单指向 2.2.5 自己）。
