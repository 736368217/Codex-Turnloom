# 端口占用误报修复与本机网关迁移（2026-11-17）

本机机器网关已从 8787 迁到 42873，SSH 反向转发同步迁移。公网地址仍为
`https://tl.z736.cc.cd`，机器访问码和两个服务访问码均未更换。

## 证据与原因

- 用户截图中的 PID 16440 经实际进程命令行核对，是本仓 `server/machine-gateway.cjs`
  的守护进程，监听 8787。它不是其他应用抢占的端口。
- 当时轻量机器身份与带鉴权的发现接口均返回 200；控制台日志在后端健康探测超时后进入重试，
  可再次复用同一 PID 16440。原启动逻辑先探默认后端 `/api/health`，超时后把健康网关当成占用者。
- 实际安装目录还残留旧版 `desktop/service/health.cjs` 和 `pairing.cjs`。
  前者缺少网关检查导出，后者生成二维码时误用服务访问码。此前只测源码没有覆盖到这两处运行副本差异。

## 修改

1. 控制器启动、重查、恢复共用 `verifiedHealth()`：先核对网关身份及带鉴权的服务发现，
   再检查默认后端。身份不符时仍拒绝复用。
2. 网关已验证而默认后端超时：复用网关，界面显示“部分可用”，保留后端异常状态并继续探测。
   这种情况不会再报告端口冲突，也不会因连续六次后端超时重启网关。
3. 运行副本补齐 `health.cjs`、`pairing.cjs`，重启实际控制台。全量比较 desktop 下的
   CJS/JS/HTML/CSS 共 19 个文件，最终 19/19 哈希一致。
4. 本机网关端口迁到 42873。迁移前确认无监听且不属于 Windows TCP 排除范围，实际 bind 成功。
   新网关通过鉴权发现校验后才关闭旧监听，并让守护重建 SSH 隧道。
