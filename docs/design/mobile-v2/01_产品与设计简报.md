# 01 产品与设计简报（V2 升级版）

## 1. 产品身份与定位

- **产品名称**：Codex-Turnloom
- **核心定位**：把正在电脑上运行的 Codex Desktop，无缝、安静、可靠地延续到你的手机里。
- **架构形态**：
  1. **Android 原生外壳**：负责电脑设备管理、扫码配对、Android Keystore 访问码加密存储、原生连接状态与系统通知。
  2. **WebView 移动工作区**：负责对话抽屉、实时消息流、工具记录折叠、权限审批决策、运行中排队/插入控制与目标管理。
  3. **电脑端本机服务**：读取 Codex Desktop 状态并通过本地 IPC 转发指令，数据 100% 留在用户自己的电脑上。

## 2. 为什么要做 V2 升级

V1 版本完成了基础功能闭环，但在真实移动场景（单手握持、通勤晃动、会议间隙快速扫视）下暴露出明显痛点：

1. **认知负荷高**：用户在手机上打开 App 的前 2 秒，最关心“任务还在跑吗？有没有卡在权限审批？”。V1 把状态写成 12px 灰色文字，反而让右上角的实心蓝色扳手按钮抢走了全屏视觉重心。
2. **操作语义费解**：当任务运行中时，V1 底部突然多出青绿色的 `[排队 | 插入]`，既把模型名称挤成 `GPT-5...`，又没解释什么叫“插入”，导致用户不敢轻易点击。
3. **高危审批易误触**：权限审批关系到电脑本地目录读写或命令执行，V1 的 `[是] [否] [一直是]` 仅有 32dp 高，且红底配绿框，单手大拇指极易点错。
4. **视觉风格割裂**：新旧两套色彩（冷灰蓝 vs 暖灰青绿）和 7 种圆角并存，缺乏成熟工具产品的秩序感与品质感。

## 3. V2 设计理念：Loom Studio（极简织机美学）

V2 以 **“安静的秩序感、零歧义的语义、单手直觉操控”** 为核心，确立八大设计原则：

1. **状态先于内容（Status First）**：顶栏和对话列表统一采用高对比度语义状态胶囊（Status Pill），无需阅读正文即可在 0.5 秒内判断“思考中 / 待审批 / 已结束 / 离线”。
2. **绝对单一操作色（Single Action Accent）**：全界面只有 `#0066CC` 一种主操作蓝，且实心深蓝只赋予当前视图最高优先级的动作（如“发送”、“允许本次”、“扫描设备二维码”）。
3. **语义自解释（Self-Explanatory Controls）**：拒绝黑话与哑谜图标。将 `排队 / 插入` 升级为 `排队（完成后发） / 插入（立即打断）`；将审批按钮升级为 `允许本次 / 始终允许 / 拒绝` 并附带原语义副标；为 `@ 插件` 与 `/ 技能` 补齐文字标签。
4. **单手拇指工程学（Thumb-Zone Ergonomics）**：所有高频交互控件集中在屏幕下半区与易于触达的 44×44dp 热区；运行态控制条与输入舱分层排布，绝不互相挤压。
5. **渐进式信息披露（Progressive Disclosure）**：合并每条消息多余的三层元信息为单行眉标；工具调用默认折叠为单行等宽路径步骤卡，需要时再点开看详情。
6. **高危操作沙盒化（Sandboxed Critical Actions）**：权限审批中的目标路径或终端命令必须独立置于等宽字体沙盒框内，让“授权对象”一目了然。
7. **原生与 Web 浑然一体（Unified Shell & WebView）**：原生电脑选择页与 WebView 工作区共享完全一致的冷灰底色 `#F4F5F8`、16dp 卡片圆角、边框与字体层级。
8. **隐私感外显（Visible Privacy）**：在电脑选择页、访问码门禁与引导页底部，以克制的锁形图标与短句明确告知“Keystore 加密、端到端直连电脑本地”。

## 4. 升级目标与量化验收指标

- **状态识别速度**：打开对话工作台后，视线定位当前任务状态的耗时 **< 0.5 秒**。
- **零截断与零挤压**：在 360dp–430dp 宽度下，品牌名 `Codex-Turnloom`、电脑名称、模型胶囊与运行中切换条 **零异常换行**。
- **触控安全达标率**：主要操作按钮（发送、停止、审批三按钮、扫码、抽屉开关）触控热区 **100% ≥ 44×44dp**。
- **色彩纯净度**：旧版青绿 `#1F6F62` / `#C9D8D3` 与暖灰 `#F6F5F2` 残留率降为 **0%**。
