# 07 设计评审与验收清单（V2 升级版）

> 用途：AI 编程代理或前端开发完成 V2 升级后，使用本清单逐项验收。

## 0. V2 专项升级必检项（一票否决项）

- [ ] **色彩纯净度**：全界面已彻底清除 `#1F6F62`、`#DCECE8`、`#F1F7F5`、`#F6F5F2` 等旧版青绿与暖灰残留，全局仅保留 `#0066CC` 唯一主操作蓝。
- [ ] **顶栏状态胶囊**：对话工作台顶栏副标题第一项为带圆点的彩色状态胶囊（`● 思考中` / `● 待确认权限` / `● 已就绪`），0.5 秒内一眼可见。
- [ ] **工具开关降噪**：右上角工具按钮不再是实心蓝色大圆 + `🔧` Emoji，而是 40×40dp 线性扳手 SVG，开启态为浅蓝底 `#E8F2FF` + 右上角 6px 蓝点。
- [ ] **输入舱与运行控制条不打架**：任务运行中时，`排队（完成后发） | 插入（立即打断）` 独立在输入框上方展示，底部模型胶囊（`GPT-5.6 | 中 ▾`）与插件/技能按钮全部单行完整显示，零折行。
- [ ] **权限审批防误触**：权限审批卡包含独立的等宽字体路径沙盒框，底部三个按钮高度 ≥ 44dp，主次颜色分明（实心蓝 / 浅蓝描边 / 浅灰红字）。
- [ ] **品牌名零断行**：访问码门禁页与顶栏的 `Codex-Turnloom` 在 360dp–390dp 宽度下始终单行展示，绝不断成两行。

# 07 设计评审与验收清单

> 用途：另一份 AI 或设计师交付后，用这份清单快速验收。
> 每一项都可以直接回答“通过 / 不通过 / 不适用”。

## 1. 信息架构

- [ ] 7 个 P0 页面齐全，且顺序清晰
- [ ] 电脑选择 → 工作区 → 对话 → 输入 → 审批/队列 的主流程不增加步骤
- [ ] 多电脑切换入口明显，不需要退出 App
- [ ] 对话列表的分组、排序、搜索、新建都能找到
- [ ] 工具记录默认收起，有明确开关
- [ ] 目标、模型、插件、技能、附件等次级功能没有被放进主流程
- [ ] 返回路径符合“浮层 → 抽屉 → 电脑列表”
- [ ] 通知深链能直接落到对应对话

## 2. 视觉层级

- [ ] 第一眼能看到“任务在运行 / 等待处理 / 已结束”
- [ ] 标题、正文、元信息有明确三级层次
- [ ] 页面只使用一个主操作蓝
- [ ] 绿色只表达在线/成功，橙色只表达运行中，红色只表达错误/等待，黄色只表达提示
- [ ] 按钮、卡片、气泡的圆角体系统一
- [ ] 阴影只用于浮层、抽屉、对话框
- [ ] 没有装饰性渐变、玻璃拟态或多余纹理
- [ ] 图标风格统一，线宽一致
- [ ] 没有用 emoji 充当功能图标

## 3. 触控与单手

- [ ] 所有主要按钮 ≥44×44dp
- [ ] 发送、停止、审批、返回在拇指可达区域
- [ ] 相邻可点击元素间距 ≥8dp
- [ ] 键盘弹出时输入区和发送按钮不被遮挡
- [ ] 长按对话有明确反馈（震动 / 菜单）
- [ ] 抽屉可以从左上按钮打开，也能通过遮罩关闭
- [ ] 滚动到顶/到底有明确反馈
- [ ] 小屏 360dp 下没有横向滚动

## 5. 文案

- [ ] 中文用短句，不使用感叹号
- [ ] 按钮使用动词
- [ ] 状态使用名词/形容词
- [ ] 错误包含“原因 + 下一步”
- [ ] 发送方式“排队 / 插入”有解释
- [ ] 审批“是 / 否 / 一直是”不歧义
- [ ] 隐私说明简短、可信
- [ ] 英文扩展不会溢出
- [ ] 时间、单位、标点统一

## 6. 无障碍

- [ ] 图标按钮有可读标签
- [ ] 状态不只靠颜色
- [ ] 正文对比度 ≥4.5:1
- [ ] 大字号下不破版
- [ ] 焦点态可见
- [ ] 对话框焦点锁定
- [ ] 动效可关闭
- [ ] 触控目标 ≥44dp
- [ ] 屏幕阅读器能读出任务状态和审批按钮

## 7. 设计系统一致性

- [ ] 颜色使用 token，不写死零散色值
- [ ] 字号使用统一 scale
- [ ] 间距使用 4pt 体系
- [ ] 圆角收敛为 4–5 档
- [ ] 图标尺寸 16/20/22/24
- [ ] 按钮高度统一（46/48）
- [ ] 输入框高度统一（48/50）
- [ ] 卡片内边距统一（12/16）
- [ ] 弹层阴影统一
- [ ] 组件命名可复用

## 8. 交付质量

- [ ] 7 个 P0 页面均为 390×844
- [ ] 每个页面至少包含默认 + 1 个关键状态
- [ ] 组件库可复用，不是每页重复画
- [ ] 设计令牌完整（颜色、字号、间距、圆角、阴影、动效）
- [ ] 交互说明覆盖关键流程和边界
- [ ] 设计理由能对应到产品目标
- [ ] 文件命名清晰
- [ ] 没有包含真实用户数据、访问码或私人地址
- [ ] 可以直接交给开发评估

## 9. 评审时必须追问的问题

1. 用户在 360dp 小屏上，第一眼能看到“运行中”还是只看到消息正文？
2. 审批失败后，用户是否知道下一步做什么？
3. 发送失败后，原文和图片是否还在？
4. 运行中，用户是否清楚“排队”和“插入”的区别？
5. 工具开关是否和发送按钮争夺注意力？
6. 多电脑场景下，用户是否能在 3 步内切换？
7. 键盘弹出时，发送按钮是否仍可见？
8. 断网时，页面是显示旧内容还是清空？
9. 颜色之外，状态是否还有文字/图标兜底？
10. 设计是否仍然像“Codex 工作台”，而不是一个通用聊天 App？

## 10. 常见扣分项

- 把“运行中”做成一个很小的灰点
- 用绿色表示所有“成功”和“在线”，用红色表示所有“错误”和“等待”，导致语义混淆
- 发送按钮、停止按钮、附件按钮大小相同且颜色都很重
- 审批按钮只有颜色，没有文字说明
- 队列条把输入区挤到屏幕外
- 工具记录默认展开，消息流被工具日志淹没
- 模型名、插件、技能在 360dp 下全部挤在一行
- 使用渐变、玻璃拟态、彩色气泡尾巴
- 把电脑选择页做成启动广告页
- 把“新建对话”做成巨大的悬浮按钮，遮挡内容
