# Codex-Turnloom 手机端 App 升级设计方案（V2 · Loom Studio）

> 版本：V2.0（2026-10-23 Gemini 升级版）
> 用途：直接交给 AI 编程代理（Codex / Claude Code / Cursor）或前端工程师落地实施
> 基准画布：Android 390×844dp（兼容 360–430dp 响应式宽度）

## 本次 V2 升级解决了什么核心问题

在保留原有产品定位（私有自托管 Codex 移动工作台）与全部功能范围的前提下，V2 方案（代号 **Loom Studio · 极简织机**）彻底解决了 V1 过渡版本的 6 大体验与视觉痛点：

1. **终结“双色系打架”，确立纯粹单一操作蓝（`#0066CC`）**：清除 V1 遗留的复古青绿（`#1F6F62` / `#C9D8D3`）与暖灰黄背景（`#F6F5F2`），全局统一为通透冷灰底（`#F4F5F8`）+ 纯白卡片（`#FFFFFF`）+ 唯一操作蓝（`#0066CC`）。
2. **顶栏“状态胶囊（Status Pill）”前置，真正实现“状态先于内容”**：将原本淹没在 12px 灰字里的任务状态提炼为高辨识度语义胶囊（`● 思考中 · 01:18` 琥珀色 / `● 待确认权限` 珊瑚红 / `● 已就绪` 翠绿色），第一眼即可掌控全局。
3. **右上角工具开关降噪，归还主视觉焦点**：取消 V1 中与发送按钮强烈抢夺焦点的“实心蓝圆 + 彩色扳手 Emoji”，改为线性扳手 SVG 按钮（开启态采用浅蓝底 `#E8F2FF` + 右上角 6px 蓝点指示），让右下角“发送”成为全屏唯一的实心蓝焦点。
4. **重构“一体式输入工作舱（Unified Composer Pod）”与“运行态内联控制条”**：
   - 将原本挤在底部一行的 6 组高低不一控件，拆分为平时极简的 `[GPT-5.6 · 中 ▾]`、`[@ 插件]`、`[/ 技能]` 胶囊；
   - 当任务运行中时，在输入舱上方内联展开独立的**发送方式控制条**：`[排队（完成后发） | 插入（立即打断）]`，自带 4 字直白说明，既不挤压模型名，又让新老用户一秒看懂“排队”与“插入”的区别。
5. **权限审批升级为“安全沙盒决策卡（Security Sandbox Card）”**：告别 V1 红底配绿按钮的 32dp 小控件，采用白底 + 顶部 4px 警示红条 + **等宽字体路径沙盒框** + **44dp 高防误触三列大按钮**（`允许本次 · 是` / `始终允许 · 一直是` / `拒绝 · 否`）。
6. **消息流减负与设备卡片独立化**：合并冗余的角色头与“已发送”废话标签，将工具记录收敛为单行可折叠步骤卡；电脑选择页升级为独立悬浮设备卡 + “最近活跃任务一键直达”横幅；访问码页优化为 24px 单行不折行标题。

# 01 产品与设计简报（V2 升级版）

## 1. 产品身份与定位

- **产品名称**：Codex-Turnloom
- **核心定位**：把正在电脑上运行的 Codex Desktop，无缝、安静、可靠地延续到你的手机里。
- **架构形态**：
  1. **Android 原生外壳**：负责电脑设备管理、扫码配对、Android Keystore 访问码加密存储、原生连接状态与系统通知。
  2. **WebView 移动工作区**：负责对话抽屉、实时消息流、工具记录折叠、权限审批决策、运行中排队/插入控制与目标管理。
  3. **电脑端本机服务**：读取 Codex Desktop 状态并通过本地 IPC 转发指令，数据 100% 留在用户自己的电脑上。

## 2. 为什么要做 V2 升级

V1 版本完成了基础功能闭环，但在真实移动场景（单手握持、通勤晃动、会议间隙快速扫视）下暴露出明显痛点：

1. **认知负荷高**：用户在手机上打开 App 的前 2 秒，最关心“任务还在跑吗？有没有卡在权限审批？”。V1 把状态写成 12px 灰色文字，反而让右上角的实心蓝色扳手按钮抢走了全屏视觉重心。
2. **操作语义费解**：当任务运行中时，V1 底部突然多出青绿色的 `[排队 | 插入]`，既把模型名称挤成 `GPT-5...`，又没解释什么叫“插入”，导致用户不敢轻易点击。
3. **高危审批易误触**：权限审批关系到电脑本地目录读写或命令执行，V1 的 `[是] [否] [一直是]` 仅有 32dp 高，且红底配绿框，单手大拇指极易点错。
4. **视觉风格割裂**：新旧两套色彩（冷灰蓝 vs 暖灰青绿）和 7 种圆角并存，缺乏成熟工具产品的秩序感与品质感。

## 3. V2 设计理念：Loom Studio（极简织机美学）

V2 以 **“安静的秩序感、零歧义的语义、单手直觉操控”** 为核心，确立八大设计原则：

1. **状态先于内容（Status First）**：顶栏和对话列表统一采用高对比度语义状态胶囊（Status Pill），无需阅读正文即可在 0.5 秒内判断“思考中 / 待审批 / 已结束 / 离线”。
2. **绝对单一操作色（Single Action Accent）**：全界面只有 `#0066CC` 一种主操作蓝，且实心深蓝只赋予当前视图最高优先级的动作（如“发送”、“允许本次”、“扫描设备二维码”）。
3. **语义自解释（Self-Explanatory Controls）**：拒绝黑话与哑谜图标。将 `排队 / 插入` 升级为 `排队（完成后发） / 插入（立即打断）`；将审批按钮升级为 `允许本次 / 始终允许 / 拒绝` 并附带原语义副标；为 `@ 插件` 与 `/ 技能` 补齐文字标签。
4. **单手拇指工程学（Thumb-Zone Ergonomics）**：所有高频交互控件集中在屏幕下半区与易于触达的 44×44dp 热区；运行态控制条与输入舱分层排布，绝不互相挤压。
5. **渐进式信息披露（Progressive Disclosure）**：合并每条消息多余的三层元信息为单行眉标；工具调用默认折叠为单行等宽路径步骤卡，需要时再点开看详情。
6. **高危操作沙盒化（Sandboxed Critical Actions）**：权限审批中的目标路径或终端命令必须独立置于等宽字体沙盒框内，让“授权对象”一目了然。
7. **原生与 Web 浑然一体（Unified Shell & WebView）**：原生电脑选择页与 WebView 工作区共享完全一致的冷灰底色 `#F4F5F8`、16dp 卡片圆角、边框与字体层级。
8. **隐私感外显（Visible Privacy）**：在电脑选择页、访问码门禁与引导页底部，以克制的锁形图标与短句明确告知“Keystore 加密、端到端直连电脑本地”。

## 4. 升级目标与量化验收指标

- **状态识别速度**：打开对话工作台后，视线定位当前任务状态的耗时 **< 0.5 秒**。
- **零截断与零挤压**：在 360dp–430dp 宽度下，品牌名 `Codex-Turnloom`、电脑名称、模型胶囊与运行中切换条 **零异常换行**。
- **触控安全达标率**：主要操作按钮（发送、停止、审批三按钮、扫码、抽屉开关）触控热区 **100% ≥ 44×44dp**。
- **色彩纯净度**：旧版青绿 `#1F6F62` / `#C9D8D3` 与暖灰 `#F6F5F2` 残留率降为 **0%**。

## 3. 导航规则

1. **App 启动**：总是先进入电脑选择页；已保存电脑并行检测在线状态。
2. **进入电脑**：点击电脑行进入 WebView；顶栏显示电脑名和在线点。
3. **返回优先级**（Android 返回键 / 手势）：
   - 先关闭当前 Web 浮层（目标编辑、模型面板、插件/技能菜单、图片选择菜单、侧栏）
   - 再关闭对话列表抽屉
   - 最后返回电脑选择页
4. **对话列表**：选择对话后自动关闭抽屉（窄屏）；抽屉可通过遮罩、返回或左上按钮关闭。
5. **新对话**：在列表中插入“新对话”草稿项，右侧显示“输入消息开始新对话”。
6. **通知深链**：点击完成提醒通知，直接打开对应电脑和对话。
7. **外部链接**：消息中的网页链接交给系统浏览器打开，不覆盖当前 App 页面。
8. **文件下载**：调用 Android 系统下载；完成后可从系统通知打开。
9. **图片预览**：在 App 内全屏预览，支持双指缩放；返回关闭预览。
10. **多电脑**：每台电脑的访问码独立保存；切换电脑不丢失当前对话草稿。

## 4. 关键流程

### 4.1 首次连接

```text
启动 App
  → 电脑选择（空状态）
  → 阅读“扫描电脑上显示的设备码”
  → 扫描二维码 / 手动输入
  → 识别设备（名称、地址、访问码）
  → 保存到手机本地（Keystore 加密访问码）
  → 回到电脑列表，检测在线
  → 点击电脑
  → 原生顶栏 + 加载进度
  → 访问码通过（或已记住）
  → 对话列表 / 最近对话
  → 使用指引（首次）
```

### 4.2 继续一个正在运行的任务

```text
打开 App
  → 电脑列表（在线）
  → 进入工作区
  → 对话列表（按项目 / 按最近）
  → 选择“运行中”的对话
  → 打开最新 40 条消息
  → 查看状态：正在处理 · 运行时长
  → 工具记录默认收起
  → 输入补充内容
  → 选择“排队”或“插入”
  → 发送
  → 看到“已排队 / 已插入 / 发送失败”
```

### 4.3 处理权限审批

```text
消息流出现红色“交互”气泡
  → 标题“等待确认”
  → 阅读请求说明
  → 点击“是 / 否 / 一直是”
  → 按钮进入“正在提交审批…”
  → 成功：“审批已提交”
  → 失败：“审批提交失败：原因” + 保留重试
```

### 4.4 多电脑切换

```text
工作区顶栏返回
  → 电脑列表（当前电脑显示在线）
  → 选择另一台电脑
  → 检测在线 / 离线
  → 在线：进入工作区
  → 离线：显示地址与“离线”，可编辑 / 测试连接 / 删除
```

## 5. 信息层级

### 对话工作台（从上到下）

1. **任务身份**：标题、消息数、运行状态
2. **目标**：一行目标摘要 + 状态（可展开）
3. **消息流**：按时间顺序；用户消息右侧、Codex 左侧、工具/提示/交互有独立语义色
4. **当前状态**：思考中 / 正在处理 / 运行时长
5. **输入区**：文本 → 附件 → 模型/插件/技能 → 发送/停止 → 队列
6. **反馈**：发送状态、错误、重试

### 对话列表（从上到下）

1. **品牌与数量**
2. **搜索 + 新对话**
3. **排序方式**
4. **分组标题（可折叠）**
5. **对话项：标题 + 状态 + 提醒标记**
6. **使用指引 / 隐私说明**

## 6. 内容与命名约定

- 对话：`对话`；任务状态：`运行中 / 等待处理 / 已结束 / 状态未知`
- 发送方式：`排队`（当前任务完成后发送）/ `插入`（立即插入当前任务）
- 审批：`需要处理`、`等待确认`、`是`、`否`、`一直是`
- 连接：`在线`、`离线`、`正在检测`
- 提醒：`提醒已开`、`完成提醒`
- 目标：`目标`、`进行中`、`已暂停`、`已阻塞`、`用量受限`、`预算受限`、`已完成`
- 错误：使用“原因 + 下一步”，例如“发送失败：网络超时”“审批提交失败：请重试”

## 7. V2 信息架构与信息层级优化补充（重要）

在严格保持上述页面结构与导航规则不变的前提下，V2 对单页内的**微观信息层级**进行了三项关键收拢：

1. **电脑选择页（S02）新增「最近活跃任务直达横幅」**：
   - 在已保存电脑卡片下方，若在线电脑存在正在运行或刚更新的任务，展示一条轻量横幅（如 `⚡ 最近活跃任务（办公室电脑）：评估手机端设计方案 · 正在思考中 [直达 →]`），让重度用户从打开 App 到进入目标任务的步数从 3 步缩短为 **1 步**。
2. **对话工作台（S08）输入区分层架构**：
   - **第一层（动态出现）**：候发队列面板（`.queue-status-bar`，仅当有排队消息时展开）。
   - **第二层（动态出现）**：运行中发送方式条（`.follow-up-mode`，仅当任务运行中时展开，独占一行展示 `排队（完成后发） | 插入（立即打断）`）。
   - **第三层（常驻）**：一体式输入工作舱（`.composer-pod`，上方为多行文本域与附件托盘，下方左区为模型/插件/技能胶囊，右区为附件 `+`、停止 `■`、发送 `↑`）。
3. **消息单元（Message Unit）二元结构**：
   - 废除 V1 的“外部角色行 + 气泡顶部状态行 + 气泡正文 + 气泡底部时间行”四层堆叠；
   - 统一为 **「外部单行眉标（角色 + 耗时 + 时间）+ 纯净内容气泡」** 二元结构，大幅提升长会话有效信息屏效比。

- [ ] **色彩纯净度**：全界面已彻底清除 `#1F6F62`、`#DCECE8`、`#F1F7F5`、`#F6F5F2` 等旧版青绿与暖灰残留，全局仅保留 `#0066CC` 唯一主操作蓝。
- [ ] **顶栏状态胶囊**：对话工作台顶栏副标题第一项为带圆点的彩色状态胶囊（`● 思考中` / `● 待确认权限` / `● 已就绪`），0.5 秒内一眼可见。

- [ ] **权限审批防误触**：权限审批卡包含独立的等宽字体路径沙盒框，底部三个按钮高度 ≥ 44dp，主次颜色分明（实心蓝 / 浅蓝描边 / 浅灰红字）。
- [ ] **品牌名零断行**：访问码门禁页与顶栏的 `Codex-Turnloom` 在 360dp–390dp 宽度下始终单行展示，绝不断成两行。

# 07 设计评审与验收清单

> 用途：另一份 AI 或设计师交付后，用这份清单快速验收。
> 每一项都可以直接回答“通过 / 不通过 / 不适用”。

## 1. 信息架构

- [ ] 7 个 P0 页面齐全，且顺序清晰
- [ ] 电脑选择 → 工作区 → 对话 → 输入 → 审批/队列 的主流程不增加步骤
- [ ] 多电脑切换入口明显，不需要退出 App
- [ ] 对话列表的分组、排序、搜索、新建都能找到
- [ ] 工具记录默认收起，有明确开关
- [ ] 目标、模型、插件、技能、附件等次级功能没有被放进主流程
- [ ] 返回路径符合“浮层 → 抽屉 → 电脑列表”
- [ ] 通知深链能直接落到对应对话

## 2. 视觉层级

- [ ] 第一眼能看到“任务在运行 / 等待处理 / 已结束”
- [ ] 标题、正文、元信息有明确三级层次
- [ ] 页面只使用一个主操作蓝
- [ ] 绿色只表达在线/成功，橙色只表达运行中，红色只表达错误/等待，黄色只表达提示
- [ ] 按钮、卡片、气泡的圆角体系统一
- [ ] 阴影只用于浮层、抽屉、对话框
- [ ] 没有装饰性渐变、玻璃拟态或多余纹理
- [ ] 图标风格统一，线宽一致
- [ ] 没有用 emoji 充当功能图标

## 3. 触控与单手

- [ ] 所有主要按钮 ≥44×44dp
- [ ] 发送、停止、审批、返回在拇指可达区域
- [ ] 相邻可点击元素间距 ≥8dp
- [ ] 键盘弹出时输入区和发送按钮不被遮挡
- [ ] 长按对话有明确反馈（震动 / 菜单）
- [ ] 抽屉可以从左上按钮打开，也能通过遮罩关闭
- [ ] 滚动到顶/到底有明确反馈
- [ ] 小屏 360dp 下没有横向滚动

## 9. 评审时必须追问的问题

1. 用户在 360dp 小屏上，第一眼能看到“运行中”还是只看到消息正文？
2. 审批失败后，用户是否知道下一步做什么？
3. 发送失败后，原文和图片是否还在？
4. 运行中，用户是否清楚“排队”和“插入”的区别？
5. 工具开关是否和发送按钮争夺注意力？
6. 多电脑场景下，用户是否能在 3 步内切换？
7. 键盘弹出时，发送按钮是否仍可见？
8. 断网时，页面是显示旧内容还是清空？
9. 颜色之外，状态是否还有文字/图标兜底？
10. 设计是否仍然像“Codex 工作台”，而不是一个通用聊天 App？

## 10. 常见扣分项

- 把“运行中”做成一个很小的灰点
- 用绿色表示所有“成功”和“在线”，用红色表示所有“错误”和“等待”，导致语义混淆
- 发送按钮、停止按钮、附件按钮大小相同且颜色都很重
- 审批按钮只有颜色，没有文字说明
- 队列条把输入区挤到屏幕外
- 工具记录默认展开，消息流被工具日志淹没
- 模型名、插件、技能在 360dp 下全部挤在一行
- 使用渐变、玻璃拟态、彩色气泡尾巴
- 把电脑选择页做成启动广告页
- 把“新建对话”做成巨大的悬浮按钮，遮挡内容
