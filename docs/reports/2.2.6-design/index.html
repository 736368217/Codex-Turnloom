把「切换」做成一件看得懂的事

2026-11-20 00:45 第三稿 · 依据随包 2.2.5（index-CC0SxfnI.js 784,932 B / 18b7bbf）与仓库当前实现 · 只做设计与规范，不改已发布包 · 第三稿补：固定区/滚动区分界、11px 最小字号、命中带实测

先说结论

  1. 「按时间/按项目」不是回退了，是从来没做成图1那样。发布版里是两个各自填充的药丸（选中变黑），不是一条 track 里滑动的 thumb。提交 dc07ebb 只改了 CSS 的排布，把它变成「可横滑的药丸条」——字面上满足了「胶囊、可滑」，视觉上不是图1。我当时验收看的是「两个视图各 5 行、44px 命中」，没有对着图1 比控件本身，这是我的漏项。
  2. 「监控」这个 tab 不必要。它四块内容里，三块在别处已经存在且同源（连接状态=头部徽标、会话数=列表长度、运行中=列表状态点）；唯一有行动价值的是「停止运行中的任务」，而那件事应该在你看到那个任务的地方做。
  3. 设备层级要三级，而且一次只露一层：电脑 → 平台（Codex / PI）→ 该平台下的 harness（服务入口）。现在的「切换电脑上的服务」把第二、三层平铺成一个列表，看不出它们属于哪台电脑。
  4. 删一个 tab、并两处、加一层动画。底栏从 3 变 2；会话页头部加一张常驻设备卡；会话行从三块（状态图标 / 标题+时间 / 预览）收到两行，项目进 meta。

1 · 三判据：必要性 / 便利性 / 易读性

逐块过一遍现在屏幕上真实存在的东西。判据不是「好不好看」，是这三问：这块信息是不是必须存在？要用它的时候够不够顺手？看得懂吗？

位置现状三判据决定
底部「监控」tab 四组卡片：运行态摘要三宫格（运行中/错误/会话）、距上次同步倒计时、连接状态、运行中的会话+停止、错误与告警、刷新按钮 必要性低：三项与别处同源，会出现两处不一致；便利性低：为了停一个任务要先切 tab；易读性中：三个数字没有单位、没有阈值，「3」到底多不多没人知道 删掉这个 tab 内容三处归位，见第 4 节。数据侧零独有字段，threadsFilter:'running' 已经存在，运行中胶囊直接复用
视图切换 两个独立药丸，选中项黑底白字（.tl-filter-chip.is-active） 必要性高（要切视图）；易读性差：实心黑与 iOS 语义冲突，也读不出「这是一个开关的两侧」 改成图1 单条 track + 滑动 thumb，300ms 跟手动画；控件移出滚动容器
会话页头部 只有「会话」标题 + 新建 +；当前电脑/平台埋在设置里，不在首屏 必要性高（换设备、确认在哪台机器时要看）；便利性低：要进设置才知道；易读性中：看不出隶属关系 加常驻设备卡 电脑名 + 平台 + 在线灯 + 模型 chip；点开三级层级
切换服务抽屉 平铺的 TapRow 列表，标题「切换电脑上的服务」 必要性高；层级缺失：看不出这些服务在哪台电脑下，也看不出换过去以后会话、模型会跟着变 三级隶属 电脑卡 → 平台 → harness，选谁才露谁
会话行 状态图标 + 标题/时间 + 预览；没有项目名，状态含义要靠猜 必要性高；易读性中：图标无文字、项目上下文缺失；320 下标题仍被预览挤压 两行 标题 + 时间/项目 meta；只有「运行中 / 待审批 / 出错」出彩色标签
搜索框 常驻 44px 必要性中（49 条会话确实要搜）；便利性中：常驻占了首屏最贵的一条 留在滚动区顶部 滚下去自然收起、回到顶部再现；不常驻、不做浮动图标
设置里的运行信息 / 更新 诊断行、更新面板 必要性高：这是出问题时唯一能自助的地方 保留 并把「错误与告警」并进来
聊天头部 标题 + 项目副标题 + 右上模型 chip 必要性高；chip 44px；无项目时不占位 保留
输入区 @ / 拍照 / 图片 / 附件 / 发送，@ 在工具行最左 必要性高；全部 44px；单手可达 保留

连接页 扫码 / 手动地址 / 公开更新入口 必要性高：首次配对唯一入口；未配对也能检查更新 保留
置顶会话组 列表最上方，仅在有 pinned 时渲染 必要性中；0 条不占位；行 44px 保留

头四行并成一张卡：电脑名 + 平台 + 在线点 + 模型 chip。分段是单条 track，thumb 只做 translateX，不重排文字。分段固定在滚动容器之外（搜索留在滚动区顶部，回顶部就能用）——2.2.5 的 rail 在 .tl-thread-scroll 里，Vera 实测 scrollTop=600 时 rail 从 y=100 变 y=-500；翻到列表中段想切视图必须先滚回顶部，换样式解决不了，必须换位置。

为什么是「一条 track + 一个 thumb」而不是「两个药丸」

  • 它表达的是同一个维度的两个值，不是两个可选按钮。一个滑动的块把这件事说清楚了；两块独立的实心药丸读起来像「两个开关」。
  • 动画只改一个属性：transform: translateX(index × 100%)。文字位置不动、不重排，所以不会有抖动，也不需要测宽。
  • 命中区不变：track 高 44，两个 cell 各占一半，拇指在轨道内移动——按下哪里就切哪个，没有「跟手位移改变点击几何」的老问题。

控件必须钉住，不能跟着列表一起滚走

实测随包 2.2.5：.tl-thread-filters 在 .tl-thread-scroll 内部，scrollTop=600 时 rail 从 y=100 掉到 y=-500，390/360/320 三档一致。也就是说会话有 49 条时，想切「按时间/按项目」得先滚回顶部——换一条灰轨道加 thumb 并不能解决这件事，所以这一轮把分界一起定死：

区放什么
固定区（不滚）标题行（44，含「+」）＋ 分段控件（44）；两者贴在安全区下沿，列表从它们下面开始滚
滚动区搜索框（在顶部，滚下去自然收起）→ 置顶组 → 会话列表 → 加载控件

代价是固定区长期占掉约 88px 加安全区；换来的是列表在任何位置都能一键切视图。搜索留在滚动区顶部而不是常驻，是 iOS 的分工——它低频、回顶部就能用，不需要新 JS，也不用长住 44px。

3 · 设备层级：电脑 → 平台 → harness（入口）

层级怎么画出来

一条脊柱 + 一个肘

从选中的电脑卡底边落一条 1.5px 竖线，每个平台卡片左侧接一个 13px 横肘。线先画（scaleY 0→1），卡片后到（40ms 错位），读起来是「它们挂在这台电脑下面」。

一次只开一层

切电脑时当前分支高度收为 0，新分支展开。不做「两台电脑的分支同时存在」——那又回到平铺列表。

未选中的电脑不消失

未选中的卡片缩到 0.985、透明度 .72、无边框。它们随时可点，但不与当前分支竞争注意力。

拟物只用在「电脑」这一层

电脑卡里有一台小笔记本（屏 + 底座）；平台和 harness 都是纯卡片。拟物是层级线索，不是装饰：只有「这是一台机器」这个事实值得用图形说。

单平台时，只有一张卡

今天真机上只发现得到 1 个 harness（直连 server、单 profile），所以装上会看到一张平台卡——那是数据现状，不是页面坏了。脊柱照画、卡片照展开；第二张卡要等网关配出两个 harness（BACKLOG 11）。

不显示假绿灯

非当前电脑不做实时探活（探测会翻全局请求作用域、打断当前机器的在途请求），所以它们不配红/绿灯，只写「上次使用 3 小时前」。harness 行的「在线」也只是发现那一刻的快照，不写「实时」。

「配对另一台」放哪

面板底部一行虚线卡 → 全屏配对页，返回回到面板，配对成功不清已有列表。不放半屏抽屉：那一步要开相机扫码，塞进抽屉后权限弹窗和取景框都会挤。

原型按 2 台画；state 层已落（3d04843：machines[]、旧单对象自动迁移、switchMachine/forgetMachine）。今天真机只有 1 台，所以默认看到一张电脑卡；第二台通过「添加一台电脑」的配对流程加入。第三层是 harness（服务入口），不是模型——模型选择仍在聊天右上角的面板里，别把两层混在一起。

换设备/换平台时，哪些东西跟着变

会话列表
跟着设备+平台的作用域走（现在是 machineId::harnessId，缓存已经按这个键存，不用改数据模型）
模型 chip
跟着当前平台：Codex 显示「可用 N 个」，PI 显示「已加入 N 个」（modelsSource，2.2.6 一起做）
新会话默认模型
按「这台电脑 × 这个平台」记上次用的那个，不再跨设备串味
离线状态
只有当前设备有灯：离线时头部那张卡直接变色，不用切 tab 才发现；其余设备写「上次使用 N 分钟前」，因为对它们探活会打断当前机器的在途请求

数据能绑什么（按当前契约核过）

平台不是实体，是 harness.kind + 显示名映射（codex→Codex Desktop、pi→PI-Desktop）。不新增 platform 字段：那要同时改 shared/machine-pairing.cjs、app 镜像和测试，2.2.6 收益不够。但有一处必须先修：deploy/machine.example.json:36 里 PI 那行的 kind 现在写的是 codex，不改就永远分不出两个平台。

界面元素可绑字段缺口 / 处理
电脑卡machines[] 的 name/host/harnessCount/lastUsedAt；当前那台另用 session.online非当前机器没有在线状态 → 不画红绿灯，写「上次使用 N 分钟前」
平台卡kind → 显示名、该 kind 的 harness 数今天真机只回 1 个 harness → 单卡是常态；PI 的 kind 需一行文档修正

6 · 规范补丁（防止下次又按字面做回去）

docs/option-a/UI_SPEC.md 增补两条，验收对着它查：

  • 分段控件：必须是「一条 track + 一个 thumb」。禁止用两个各自填充的背景色表示选中（现状 .tl-filter-chip.is-active 的黑底药丸即为反例）。禁止用 left/width 做动画；只允许 transform。
  • 设备层级：必须是「电脑 → 平台 → harness（入口）」三级；切换电脑时才渲染该电脑的平台，切换平台时才渲染 harness。禁止把三层平铺进同一个列表（现状「切换电脑上的服务」抽屉即为反例）。
  • 平台判别：平台 = harness.kind + 显示名映射。新增/区分平台前，先确保 deploy/machine.example.json 里那一行的 kind 写对（PI 那行今天是 codex）。禁止在 UI 里按 name 字符串猜平台。
  • 分段控件的位置：必须放在滚动容器之外。放进 .tl-thread-scroll 就会随列表滚走（2.2.5 实测 scrollTop=600 时 rail 到 y=-500），这条与「长什么样」同等重要。

这些都能写成机器判据：DOM 里存在且只有一个 [data-seg-thumb]；点击第二个 cell 后 thumb 的 getBoundingClientRect().left 落在第二个 cell 内 ±1px；设备切换后 DOM 中平台节点的 data-machine 只有一个值。
