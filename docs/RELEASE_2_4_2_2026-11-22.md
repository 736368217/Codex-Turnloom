# 2.4.2 — 导航、更新、来源标、默认 PI（2026-11-22）

App `2.4.2`（versionCode `101`）· 电脑端服务同步升级（内嵌同一颗 APK）

这一版只收 Human 20:33 点名的四条，外加两条上一轮没做到、但属于发布卫生的漏项。没有新功能。

## 1. 底部导航：不再「按一下蓝一块」，选中态真的亮

**根因不是配色，是两条死规则叠在一起：**
- `.tl-tabbar [role="tab"] * { color: #636366 !important }` 把选中态的蓝压回灰色——所以三个 tab 平时一样灰，选中的只有按钮自己有颜色，图标和文字都不亮；
- `:active` 给整块 1/3 宽的按钮铺了 `rgba(0,122,255,.07)` 蓝蒙版——这就是按下去蓝一块的来源。

**现在：**
- 选中：图标与文字同为墨色 `#1C1C1E`，label 600；未选中 `#8E8E93`、500；按钮本体背景恒为 `rgba(0,0,0,0)`。
- 按下只降 `svg` 与 `.tl-tabbar-label` 的透明度（120ms），不加背景、不加 transform；毛玻璃不跟着变。命中高度仍 56px。
- 证据：390 与 320 两档，`getComputedStyle(svg).color` 选中 `rgb(28,28,30)` / 未选中 `rgb(142,142,147)`；按住时 `svg.opacity=0.5`；按下带均色 ΔE76 = 0.69（390）/ 0.63（320），max(B−R)=4；整条 tabbar max(B−R)=5/6。14 张对照截图在 `docs/qa/visual/2.4.2-nav-avatar/`。

## 2. 更新：启动自己查，一次点击开始装

**根因：** 自动检查写在 `UpdatePanel` 的挂载 effect 里，而 `UpdatePanel` 只在「设置 → 版本行 → 弹层」打开时才挂载——冷启动根本没有检查。弹层里还叠着手动检查 / 下载 / 暂停 / 打开安装界面四行。

**现在：**
- `AppRoot` 在启动（工作台就绪后）和回到前台各查一次；未配对时只静默查公网清单，不弹。
- 有更新 → 自动弹**一张**底部 sheet：`立即更新` / `稍后`。点「立即更新」→ 下载 → 校验 → 自动拉起系统安装器（安装器本身仍需系统确认，这是 Android 的边界）。
- 冷启动到开始下载：**1 次点击**；从设置版本行进入：**2 次点击**。
- 进度、取消、失败都在同一张 sheet；「稍后」或下滑关闭后，同一版本在本进程内不再自动弹，新版本号可以再弹。
- 设置只留版本行三态：`已是最新 · HH:mm` / `有更新 X` / `检查失败`。没有拿到清单时绝不写「已是最新」。
- 冷启动时若已有别的 sheet（诊断/链接）开着，更新弹层不叠加；关掉后补弹，不丢。
- 真机边界外的 bug：前台重校验的 scope 切换会取消在途请求，曾把公网清单请求 cancel 成 `status 0`，新版本被静默吞掉；现在后台检查在会话落定前不发起、留一次排队重跑，手工点不受影响。

**门禁：** 真实 bundle + 夹具电脑 + 记录型 update 桥，390×844 与 320×568 各 **36 PASS / 0 FAIL**。关键格：冷启动零点击进 DOM、`downloadUpdate` 调用 0；点一次 → 1 次，URL/sha/无 token 全对；ready → `installUpdate` 恰好 1 次；失败不写成已是最新；不叠 sheet；未配对不弹。

## 3. 来源头像：浅底墨色字形，不再是黑底白字

上一轮报告说「已改」不成立：`--tl-source-avatar` 还是 `#3A3A3C`、白字 `CX/PI`。这一版把它从 token 到像素一起换掉：

- 浅底 `#ECECF0` + 墨色 `#1C1C1E`；Codex 用 Lucide `Terminal`，PI 用 Lucide `Pi`，未知平台保留两位字母兜底（双机夹具里的 `claude` 渲染为 `CL`，不是空块）。
- 20/24 两档；会话页当前电脑行 20、设备平台卡 24、对话行 24、非当前电脑平台组 20，四处同一组件。
- 采样亮度 **0.841**、对墨色对比 **14.4:1**；`#3A3A3C` 在 `app/src` 已 0 命中。

## 4. 默认 PI：显式选择 > PI > 电脑端默认

- 规则收在 `machineRegistry.preferredHarnessId` 一处，新配对、冷启动重校验、401 自愈、设备页点选全走它。
- 旧注册表（没有 `harnessExplicit`）迁一次：有 PI 就落 PI；之后用户在设备页点 Codex 记为显式选择，成功重校验也不会被 PI 规则翻回去。
- 401 自愈先探显式/规则首选，退到兜底时把 `harnessExplicit` 写回 `false`，不把兜底伪装成用户选择。
- 设备页默认展开当前 harness 所在平台；电脑端 `defaultHarness` 不再写成「默认入口」，改「本机服务」。

**测试：** `app-harness-default` 12/12、`app-state-recovery` 24/24（含「显式 codex → 成功重校验仍是 codex」「401 回退写回 false 并序列化回读」两条真路径）。

## 5. 两条上一轮没做到的发布卫生

- **2.4.1 发布 APK 是 `debuggable=true`**（aapt2 实测）。2.4.2 用 `-BuildType release` 出包，`aapt2` 无 debuggable；`release-github.mjs` / `publish-r2.ps1` / `package-server-upgrade.ps1` 三道闸现在都拒绝 debug 包（文件名 + 合并后的 manifest 双重证明），并用 2.4.1 的 debug 包做了拒绝回归。
- **`APP_IDENTITY` 漂移**：一直是 `2.4.0 / 99`，2.4.1 都没跟着走。改成 `2.4.2 / 101`，新增 `test/app-identity.test.cjs` 锁住 `app/package.json` / `build.gradle.kts` / `APP_IDENTITY` 三处逐字一致。
